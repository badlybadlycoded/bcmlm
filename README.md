# bcmlm

This is the code for the Badly Coded Mailing List Manager (BCMLM).  BCMLM allows a small organization to run mailing lists that reach different audiences, such as customers, vendors, employees, or donors.  Authorized senders can reach the mailing list via email directly for convenience, and users can unsubscribe themselves via email or a web interface. Administrators within the organization (or possibly externally) can manage lists using a lightweight web application.  Running BCMLM requires the ability to self-host an email and web server.

The directory `mbm` contains the code for the MailBox Manager component, which monitors mailing list inboxes for incoming emails.  Emails from authorized senders are forwarded to the entire list.  List subscribers can unsubscribe with an "UNSUBSCRIBE" message, or request to have their subscription moved to a new email address with a "MOVED" message (from the new address), with the content `MOVED <old@address>`  in the email body.  Authorized mailing list administrators can add new authorized senders (SENDER), subscribe new receivers (SUBSCRIBE), or unsubscribe (UNSUBSCRIBE) current receivers.  The main loop is in the file `mbm.cpp`.

The directory `mlm` contains the code for the MailList Manager component, a [CrowCpp](https://crowcpp.org/)-based lightweight web application for managing individual mailing list.   It establishes "routes" for unsubscribing and login.  For authenticated users (authenticated through emailed link codes), the server recognizes two types of users.  Platform admins can make configuration changes to any list, add or delete lists, and add or delete platform admins.  List admins, specified by the individual mailing list configurations, can edit the lists of senders and subscribers for their lists, but cannot add other list admins or view/edit lists for which they are not admins.  The main loop is in `mlm.cpp`, with code for other functions in other files.

The `install.sh` script will fetch the necessary dependencies, create the expected directory structure, and install both servers as `systemd` services. Once installed, you can start the processes using `systemctl start bcmlm`, `systemctl start bcmbm`, stop them using `systemctl stop bcmbm` and `systemctl stop bcmlm`, and see output logs with `journalctl -u bcmbm` or `journalctl -u bcmlm`. (These commands need to be run as root, so you should run them using `sudo`.)
